DNS: cómo un nombre encuentra su dirección IP

Cuando escribes un dominio, DNS ayuda a encontrar la dirección que necesita tu equipo para iniciar la conexión. Sigue la consulta paso a paso y resuelve el reto en una terminal simulada de RINXI.

¿Qué hace DNS?

DNS es el sistema distribuido que relaciona nombres de dominio con datos útiles para la red. Para una página web, una consulta frecuente busca la dirección IP asociada a un nombre. Así puedes recordar un nombre en vez de memorizar una dirección numérica.

Piensa en una agenda de contactos que está repartida y organizada por niveles. Tu equipo pregunta a un resolver recursivo; este puede responder desde su caché o buscar la información en los servidores DNS correspondientes.

El recorrido de una consulta

1

Tu equipo pregunta
El navegador o sistema solicita la dirección para un dominio.

2

El resolver busca
Primero revisa su caché. Si hace falta, sigue referencias por la jerarquía DNS hasta un servidor autoritativo.

3

Vuelve una respuesta
El resolver devuelve el registro encontrado y puede guardarlo en caché durante su TTL.

Registros que veremos

TipoQué relaciona
ANombre con dirección IPv4
AAAANombre con dirección IPv6
CNAMEUn nombre con otro nombre
MXDominio con servidores de correo
TTL indica cuánto tiempo puede conservarse una respuesta en caché, normalmente expresado en segundos. Al vencer, el resolver puede consultar de nuevo.

Tu objetivo

Consulta aula.rinxi.test. Encuentra la respuesta del registro A, identifica la dirección IPv4 y compara el resultado con una consulta AAAA.

Objetivo esperado: registro A → 192.0.2.42; no hay registro AAAA en este escenario.

Cómo probarlo

Escribe dig aula.rinxi.test A en la terminal. Lee el nombre consultado, el tipo A y el dato que aparece en ANSWER SECTION. Después prueba dig aula.rinxi.test AAAA para observar una respuesta sin dirección IPv6.

También puedes usar nslookup aula.rinxi.test, pulsar los botones de ejemplo, solicitar una pista o escribir help.

Todo es una simulación: no se ejecutan comandos del sistema ni se consulta DNS real. El dominio termina en .test, reservado para pruebas, y las IP usadas son direcciones de documentación.

Fuentes y uso responsable

El recorrido descrito es una introducción simplificada al sistema DNS. Para ampliar, consulta RFC 1034 y RFC 1035. El sufijo .test está reservado para pruebas (RFC 6761) y 192.0.2.0/24 para ejemplos y documentación (RFC 5737).
