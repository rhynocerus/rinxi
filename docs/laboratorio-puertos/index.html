Redes · práctica 01

Puertos abiertos, cerrados y lo que podemos aprender de ellos

Un primer acercamiento al escaneo de puertos: qué significa cada estado y cómo leer una salida sencilla de Nmap. Al final podrás probarlo en una terminal educativa de RINXI.

¿Qué es un puerto?

Un equipo conectado a una red puede ofrecer distintos servicios: una página web, una conexión remota o el envío de correo, por ejemplo. La dirección IP ayuda a localizar el equipo; el puerto identifica el punto de comunicación asociado a un servicio.

Podemos imaginar la IP como la dirección de un edificio y los puertos como entradas destinadas a diferentes funciones. La comparación es orientativa: en una red, cada puerto usa reglas y protocolos concretos.

¿Qué indica el estado?

  • Abierto: el equipo acepta conexiones en ese puerto; normalmente hay un servicio escuchando.
  • Cerrado: el equipo responde, pero no hay un servicio aceptando conexiones en ese puerto en ese momento.
  • Filtrado: un filtro o la falta de respuesta impide determinar si el puerto está abierto o cerrado.
Una observación no es un diagnóstico. Encontrar un puerto abierto no demuestra que el servicio sea vulnerable. Solo indica que está disponible para comunicarse.

Puertos de ejemplo

Algunos números habituales son 22 para SSH (acceso remoto), 80 para HTTP (web) y 443 para HTTPS (web cifrada). Un servicio puede usar otros puertos, así que el número por sí solo no confirma qué programa hay detrás.

¿Qué hace Nmap?

Nmap envía solicitudes de red al objetivo indicado y clasifica las respuestas. Con opciones como -sV también intenta identificar el servicio y su versión. En un uso real, el resultado depende de la red, los filtros y la configuración del equipo.

Tu objetivo en este ejercicio

Consulta el servidor didáctico demo.local y distingue qué puertos aparecen abiertos y cuál aparece cerrado. Después identifica el servicio del puerto 22.

Objetivo esperado: 22 y 80 abiertos; 23 cerrado; servicio SSH en el puerto 22.

Cómo probarlo

En la terminal, escribe nmap -sV demo.local y pulsa Ejecutar. Lee las columnas PORT, STATE y SERVICE. También puedes usar los botones de ejemplo, pedir una pista o escribir help.

Todo lo que aparece en esta terminal es una simulación educativa. No se ejecuta Nmap ni se envían paquetes a una red. Los comandos, el dominio y los resultados están preparados para este ejercicio.

Uso responsable

En redes reales, escanea únicamente equipos propios o aquellos para los que tengas autorización expresa. Un escaneo puede activar alertas o afectar servicios; respeta siempre las normas de la organización y el alcance autorizado.
